# Intrinsic-assisted diffuse relighting (stage24)

Run `python tools/reconstruction/estimate_lighting.py INPUT_PACKAGE --output NEW_PACKAGE --lighting-backend intrinsic-assisted`.
The offline process reuses geometry, segmentation, material and intrinsic files. No model inference or dependency installation is involved. `robust-directional-ambient` remains the explicit I/A baseline; `manual-test` remains explicit calibration. The Inspector provides **Fit intrinsic-assisted diffuse**, alongside **Fit saved observations** (baseline).

The new backend uses the same bounded spherical search, nonnegative RGB coefficients and Huber solver. Observed intrinsic shading is divided by one fixed median luminance over supported pixels; exposure is zero and all color gains are one. There is no per-pixel calibration. Both source and target are still evaluated by `ImageShading.hlsl`, using travel direction and `max(dot(normal,-direction),0)`. The ratio denominator is calculated source shading, never the intrinsic observation.

Optional strict `lighting.json.assistance` v1 records the requested backend, accepted/fallback reason, intrinsic JSON SHA256, baseline/candidate light and fit statistics, scalar normalization and common normalized-gauge region comparisons. Each observation's median is one; native scale differences are recorded, not interpreted as absolute illumination. Existing lighting and ScenePackage v1 remain readable. Changed intrinsic metadata invalidates dependent lighting; `estimate_intrinsic.py` removes only that derived directory in its private copied output, leaving the old package intact.

Support is a conservative heuristic from intrinsic validity, black albedo, reconstruction error, shading ensemble uncertainty and non-diffuse fraction. For linear components A,S,R, `f=max(abs(R))/(max(A*S+abs(R))+.02)`, `support=exp(-error/.15)*exp(-uncertainty_S/.15)*clamp(1-f/.5,0,1)`. Fit additionally uses existing normal/MR/region/RGB exclusions and discards support below .1. Proxy data is not independent and falls back. An unidentifiable candidate also falls back, even if its residual is lower.

GPU qualityB now stores shadow risk, intrinsic support, clipped residual fraction and availability. Support multiplies edit confidence only for an accepted intrinsic fit with **Intrinsic diffuse protection** enabled. It does not replace RGB, subtract residual, move highlights or remove shadows. Source/target identity and strength zero remain exact. Debug keys `diffuse-support` and `protected-residual` append to old numeric values; existing intrinsic/calculated shading and effective ratio views provide comparisons. The global scale appears in the lighting Inspector and capture metadata.

Validation entry points: `tools/Validate-Diffuse.ps1`, `tools/reconstruction/verify_diffuse.py`, `tests/test_diffuse.py`. The fixed synthetic comparison deliberately biases material albedo; it is an improvement test under stated assumptions, not evidence that every real input improves. Three saved real samples include planar test geometry for outdoor/painting, which must report degeneracy.
